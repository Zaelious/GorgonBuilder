## Implementation

- `EquipmentPlanner` owns one transient mod-browser state. A visible Search mods field and default-closed Mod Browser Settings control every item's existing Available browser. Target preview, category switches, All skills and Other slots & profiles survive row closure/switching. They remain separate from persisted minimum-equipment-level preferences and the build JSON.
- Existing item-specific slot/profile relevance, active-skill outside-profile discoveries, Generic/Unknown caveats, exact alternative tiers, candidate selection and imported working-power editing continue through their existing logic.
- Expanded equipment order is compatibility/source warnings, STATS, Available/Selected, compact actions, then a single default-closed Item details & source disclosure. The disclosure preserves actual imported level/rarity/location/source slot, historical powers and tiers, imbues/unknown entries, original metadata/identifiers, published requirements, descriptions, official provenance and acquisition data. Raw saved instance details remain inspectable. No duplicate item heading/artwork appears above STATS.
- Imported historical evidence is separate from effective working powers. Source/base slot conflicts and a concise unresolved-source notice remain visible outside collapsed metadata; unresolved working pairs still appear in STATS/Selected guidance.
- Clear build uses native confirmation, `createDefaultBuildDocument` with the loaded data version, and the existing `BuildEditor.apply`/500ms autosave path. Cancel makes no reset edit or save. Confirm replaces the whole working document and clears the skill-change Undo/detail state. Existing read-only protections disable it. Imported reports/My Items, preferences and unrelated local data survive; there is no storage-key deletion or second persistence mechanism.

No new dependencies. No changes to data/generated artifacts, eligibility/tier interpretation, damage, Spark simulation, ability behavior, import parsing, remote persistence or BuildDocument v1.

## Customer hands-on checklist

1. Search **lightning** with the shared mod search. Change categories, All skills and Other slots & profiles; switch Head, Chest, Ring and Necklace. Verify the controls remain selected and there is one toolbar.
2. Try **Max**, **90**, **100**, a custom number and invalid text. Verify last-valid preview retention and the independent minimum-equipment-level picker.
3. Expand a database item and imported Head/Necklace. STATS should be immediately readable; open Item details & source to inspect actual levels, requirements, IDs, historical powers, imbues and acquisition/source information. Important warnings stay visible.
4. Edit/remove/restore an imported working treasure power; add/remove a candidate. Check immediate STATS changes and unchanged historical evidence.
5. Populate both skills/bars, equipment, imported powers, mods, Sparks, title/notes and target settings. Cancel Clear build and verify no changes.
6. Confirm Clear build, wait for Saved and refresh. Verify the standard default build. Before refreshing, verify My Items still contains the imported inventory; after refresh the separate in-memory report session follows its existing reimport behavior. Minimum-level preferences persist through both reset and refresh.
7. Verify protected drafts cannot reset. Repeat keyboard interaction and narrow layouts at 375px/320px; check the console.

## Risks, assumptions and follow-ups

- Private customer exports were not used. Their mapping/resolution accuracy remains a customer hands-on follow-up from earlier import tickets. Synthetic source evidence and exact working pairs were exercised here.
- Mod target/search/filters remain session-only; refreshing returns them to defaults. Minimum equipment level remains a persisted browser preference. Imported inventory survives Clear build within the current page; the existing import session still clears on refresh.
- Published treasure profiles remain generation-pool evidence, not proof of final equip legality; all existing caveats remain.
- **Pre-existing issue, outside this ticket:** on untouched accepted main `50b1a3d`, a 375px viewport expands to **501px** when saved bar entries mismatch their selected skills and trigger “Marked slots need review.” Reproduced using Druid/Archery with mismatched `ability_1578`/`ability_1201` entries; a separate untouched-main Vite server reproduced the same measurements. Matching ability selections pass this ticket's 375/320px checks. Follow-up should repair warning-content sizing in the ability-bar layout; no ability code was changed here.
