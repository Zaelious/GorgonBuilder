product owner's in-app screenshot approval. **Do not merge automatically.**

## What changed

- **Tokens/typography (`src/styles/global.css`):** charcoal palette (`#0f0f0f` page, `#1a1a1a` panel, `#141414`
  inputs, `#222222` empty slots, `#2a2a2a`/`#333333` borders, `#f2f2f2`/`#9a9a9a`/`#858585` text), Skill A blue
  `#3b82f6`, Skill B amber `#eab308`, green `#22c55e` positive/mod actions, red `#ef4444` destructive. Inter with
  system fallbacks (no font package). Serif headings and green-tinted surfaces removed; blue focus ring everywhere.
  Bronze/gold appears only in the artwork.
- **Header (`BrandHeader.tsx`, `brand-header.css`):** ~96 px desktop / ~72 px mobile cinematic header; portrait,
  “Gorgon Builder” wordmark and muted “Build Planner” label (hidden below 368 px).
- **Heading actions:** save status, Import Character (upload icon), green **Save**, quiet red-on-hover Clear build.
- **Save** (`aria-label="Save local draft"`): calls the existing `autosave.schedule(current) + flush()` path, so it
  writes the browser draft immediately and shows the real result (“Saved in this browser” / “Changes are not saved” +
  Retry). Disabled for protected/read-only drafts. No remote save; the 500 ms autosave is unchanged.
- **Skills:** blue/amber guide bars and labels per row, ~52 px tiles with the skill accent on filled tiles, quiet
  empty tiles (+ on hover/focus), green bare + picker. Two selectors, levels, six slots, quick remove, Apply imported
  level, legacy/warning states unchanged. **No `+88%`/`+110%` badges**: no trustworthy per-ability value exists before
  T0013, so the label is omitted rather than invented.
- **Equipment:** each of the nine primary rows (and Other slots) shows icon, bold slot label over the item name /
  italic “No gear selected”, status, and a chevron. Expanded STATS, Available/Selected, shared mod search, Mod Browser
  Settings, help, My Items and pickers keep their behavior with the new surfaces.
- **Ability inspector:** the same hover/focus/click floating popover (150 ms hover handoff, Escape + focus return,
  viewport flip, internal scroll, touch). Now: 40 px official icon, 18 px title, description, one vertical
  `Label: Value` list — Damage, Health/Armor damage, If vulnerable, Power cost, **Reuse time**, Range, Min level — with
  damage values in their damage-type color, green “Relevant Mods” list (no blue callout), effects, bordered Technical
  details and Edit bar disclosures, then a subtle red Remove.
- **Dialogs/notices:** ability picker, equipment picker/My Items, import dialog, warnings and error notices use the
  same surfaces, borders and controls; touch targets stay ≥ 44 px on coarse pointers (dialog/popover close included).
- **Mobile overflow fix:** the “Marked slots need review” bar message widened the slot grid's max-content track and
  pushed 375 px layouts to ~507 px (reproducible on unmodified main). It now fills the bar width without sizing the
  track.

## T0022-F2 — Compact, single-column ability tooltip

Ticket: `docs/Tickets.md` → T0022-F2. Compared against the product owner's two 2026-11-02 screenshots (preferred
compact tooltip vs. the rejected wide inspector).

- **One narrow column, simple placement** (`src/features/abilities/popover-placement.ts`, pure, 7 unit tests): fixed
  440 px desktop width (hard cap 480 px; viewport-bounded on phones), never widened or split. Below the slot, then
  above (horizontal clamp only), then a narrow card beside the slot; on narrow screens without side room the whole card
  stays inside the viewport near the slot. Only content taller than the viewport scrolls, in a bounded full-height
  column with the title/close pinned. Hover hand-off (150 ms), click pin, focus/keyboard, Escape + focus return,
  collision handling and re-placement when disclosures open are unchanged.
- **Density through typography:** 15 px title, 30 px icon, 13 px description/facts, 12 px mod effects, line-height
  ~1.28, 11–12 px padding, 4–6 px section gaps, 28 px desktop disclosure rows (44 px on coarse pointers). Damage-type
  colors and the green Relevant Mods heading are kept.
- **Order:** header → description → stats → the ability's own effects (plain lines) → Relevant Mods → Technical
  details / Edit bar → Remove.
- **Exact mod wording:** every Relevant Mod renders its full official description once per source instance (e.g. each
  “Chew Cud increases…” line), unchanged, unmerged.
- **Provenance on demand:** no per-row “Chest”/“imported” tags. Each row keeps `data-relevant-mod`, `data-power-id`,
  `data-tier-id`, `data-source-slot`, `data-source-kind`, a `title`, and `aria-describedby` pointing to its entry in
  **Technical details → Relevant mod sources** (same order): slot, item name, planned/imported, power/tier and match
  evidence — reachable by keyboard (Tab into the card, Enter on Technical details).
- **Non-damaging abilities:** when no damage is published and the type is `Nothingness`, the primary list omits the
  empty Damage line; Technical details states “Damage: not published (damage type Nothingness …)”. Real or
  “Not published” damage of any other type is still shown.
